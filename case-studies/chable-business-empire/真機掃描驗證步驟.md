## 執行

1. **先開 watcher**(電腦端,在掃描前啟動,才能捕捉掃描當下):
   ```bash
   cd chable/bot
   node scan-verify.js --interval 30 --max-minutes 30
   ```
   它會每 30 秒用同帳號查一次台北 101 的 marketplace,listings 一出現就 dump。

2. **到台北 101 附近**(或把手機帶到 25.0330, 121.5654 方圓 ~1km 內)。

3. **掃描**:
   - 打開 Chable App → 下方 **Scan** 模組
   - 點 **View Nearby**(或「掃描附近商家」),等它跑出商家清單(7-Eleven、全家、麥當勞…)
   - 若 App 提示定位太快/距離太遠,停幾秒再試

4. **看結果**:
   - watcher 印出 `✅ 掃描後 listings 出現!` + 第一個 listing → **假說證實**(掃描→listings)
   - 同時在 App 的 **Marketplace** 畫面確認那些商家是否以可購買 listing 出現
   - 若 30 分鐘內都是 `listings=0`:記錄下來,代表掃描後仍未播種(或掃描未成功寫入)

## 買店價格信任測試(掃描成功、listings 出現後)

兩種方式擇一:

1. **一條龍**(推薦):掃描前就加 `--buy` 開 watcher——listings 一出現,自動接買店測試:
   ```bash
   cd chable/bot
   node scan-verify.js --buy --interval 30 --max-minutes 30
   ```
   買店測試邏輯(`bot/purchase-trust.js`,共用):用第一個**真實 listing 的實際欄位名**組 payload,
   **先試篡改價(1 / 10 / 半價)再試原價**,任一 200 即停:
   - 篡改價成功 → **伺服器未驗證 chargedPurchasePrice(價格信任漏洞,需通報)**
   - 全部失敗 → payload 欄位名仍不符或伺服器驗價(維持未達,記錄失敗模式)

2. **手動**:watcher 抓到 listings 後,再跑一次:
   ```bash
   node probe-marketplace.js --account test_pentest_03@chable.test --buy
   ```
   (同一套篡改價優先邏輯;`--buy` 才真的購買。)

> 購買動作會真實寫入 production(LoA 範圍內、自己的測試帳號);測完把輸出存進
> `reports/scan-verify-YYYY-MM-DD.log`。若買到店,storeId 可留給跨帳號擁有權測試。

## 如果掃描後仍無 listings,可能的解釋

| 假說 | 判據 |
|---|---|
| 掃描沒寫進 `nearby_scan_cache`(App 端失敗) | App 內 View Nearby 沒跑出商家 |
| 掃描寫了,但 listing 只在「掃描當下」的那個 tile | watcher 位置與手機 GPS 不同 cell(把 watcher 的 lat/lon 改成手機實際座標再試) |
| 掃描後要等一段時間(伺服器批次) | 拉長 `--max-minutes` 到 60–120 |
| 掃描 cache 只是門票,listings 由伺服器另播種 | 同一帳號換城市掃描、隔天再查,交叉比對 |
